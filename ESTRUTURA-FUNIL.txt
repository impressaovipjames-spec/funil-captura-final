FLUXO DO FUNIL
--------------
1. Usuário acessa "/" e vê formulário de captura
2. Preenche nome e email
3. Ao enviar, dados são validados e sanitizados
   - Middleware valida estrutura da requisição
   - Validação de email com regex: /^[^\s@]+@[^\s@]+\.[^\s@]+$/
   - Sanitização remove caracteres perigosos (<>)
   - Lead salvo em memória
   - Lead persistido em leads.json automaticamente
   - Backup criado em leads.bak.json
   - Nome armazenado em localStorage
4. Redirecionamento para "/confirmacao"
   - Exibe mensagem personalizada com nome do lead
5. Link para acessar "/entrega"
   - Exibe saudação personalizada com nome do lead

SEGURANÇA E VALIDAÇÃO
----------------------
- Middleware customizado valida requisições POST /api/leads
- Validação de email com regex robusto
- Sanitização de entrada remove caracteres <> (XSS básico)
- Validação de tipos (string) antes do processamento
- Error handler universal captura todos os erros
- Respostas padronizadas: { success, message, data }
- Sem bibliotecas externas de segurança

ROTAS DA API
------------
POST /api/leads
  Request: { nome: string, email: string }
  Response: { success: bool, message: string, data: Lead }

GET /api/leads
  Response: { success: bool, message: string, data: Lead[] }

GET /leads (Debug)
  Response: { success: bool, message: string, data: { total: number, leads: Lead[] } }

GET /healthcheck
  Response: { status: "ok" }
